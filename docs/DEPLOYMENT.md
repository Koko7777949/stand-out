# النشر للإنتاج — الاستضافة، الدومين، والتوسع

هذا الدليل يغطي: أين يُنشر المشروع، لماذا GitHub Pages لا يكفي، خطوات النشر عمليًا، وقائمة فحص الإنتاج، وخطة استيعاب عدد كبير من المستخدمين المتزامنين.

---

## 1) GitHub Pages يصلح ليه؟

GitHub Pages يعرض **ملفات ثابتة فقط** (HTML/CSS/JS) بدون سيرفر. موقعنا محتاج تشغيل فعلي على السيرفر:

- جلسات دخول وأكواد تحقق واتساب/إيميل.
- قاعدة بيانات (مستخدمون، حجوزات، دفعات، تذاكر).
- منطق الدفع وتوليد الـ QR الموقّع وإدارة الأدمن.

إذن GitHub Pages **لا يصلح** إلا لو قررت تعمل الواجهة ثابتة وتشتري خدمات Backend جاهزة (BaaS) منفصلة. الحل الأنظف والأرخص صيانة: نشر Next.js كامل على واحد من التالي.

## 2) الخيارات الموصى بها

| الخيار | يناسب | السعر التقريبي | الخطوات |
|---|---|---|---|
| **Vercel** ★ الموصى به | إطلاق سريع بدون إدارة سيرفرات | مجاني للبداية ثم حسب الاستخدام | اربط الريبو → Vercel يتعرف على Next.js تلقائيًا → أضف متغيرات البيئة → Deploy |
| **Railway / Render** | تشغيل بنفس بنية الإنتاج standalone | ~5$/شهر | `bun run build` ثم `bun run start` مع Postgres مدمج |
| **Fly.io** | تحكم أعلى + مناطق متعددة | حسب الاستهلاك | Dockerfile بـ standalone + Postgres مُدار |
| **VPS (Hetzner/DO)** | أرخص على المدى الطويل + تحكم كامل | 4–10$/شهر | Docker Compose: app + Caddy (SSL تلقائي) |

> قاعدة البيانات: ابدأ SQLite للتجربة، وفي الإنتاج من أول يوم استخدم **Postgres مُدار** (Neon / Supabase / Railway) — الانتقال = سطرين في الإعدادات (انظر تحت).

## 3) خطوات النشر على Vercel (الأسرع)

1. **الريبو على GitHub** — المشروع جاهز (راجع README).
2. **قاعدة بيانات Postgres**: أنشئ مشروعًا على Neon أو Supabase واحصل على `DATABASE_URL` (يفضّل Pooler connection).
3. **`prisma/schema.prisma`**: غيّر `provider = "sqlite"` إلى `provider = "postgresql"` ثم:
   ```bash
   bunx prisma generate && bun run db:push
   ```
4. **متغيرات البيئة في Vercel** (Project Settings → Environment Variables):
   - `DATABASE_URL` — رابط Postgres
   - `SESSION_SECRET` و `QR_SIGNING_SECRET` — ولّدهما: `openssl rand -hex 32`
   - `RESEND_API_KEY` + `EMAIL_FROM="Stand Out <no-reply@yourdomain.com>"`
   - مفاتيح مزود واتساب (UltraMsg أو Meta…) — أو ادخلها لاحقًا من لوحة الأدمن
   - `ADMIN_PHONES` — أرقام المسؤولين (الافتراضي: `01200506224,01107548985`)
5. **Deploy** → اربط الدومين (مثل `tickets.standout.eg`) من Vercel → SSL تلقائي.
6. **بعد أول Deploy**: ادخل برقم مسؤول → كود واتساب → كلمة سر → **غيّر كلمة السر فورًا** → تاب الإعدادات: فعّل `hideDevOtp` → تاب حسابات الاستلام: ضع أرقامك الحقيقية.

### خطوات VPS باختصار

```bash
# على السيرفر
git clone <repo> && cd stand-out
bun install && bun run build
# .env جاهز + DATABASE_URL لـ Postgres
bun run db:push
bun run start   # standalone server على 3000
# Caddyfile: proxy localhost:3000 + SSL تلقائي للدومين
```

## 5) الأداء والمستخدمون المتزامنون

### المدمج جاهزًا
- استعلامات مفهرسة + تحرير المقاعد المعلقة تلقائيًا + معاملات ذرّية (مفيش بيع زائد للمقاعد).
- حماية ضغط على المسارات الحساسة (OTP، الدفع، الاستبدال) — limiter في الذاكرة.
- واجهة خفيفة: صفحة واحدة، حركة GPU، تحميل سريع على الموبايل.
- Idempotency على الدفع وتعارض المراجع يُرفض — نفس الطلب مايتكررش.

### عند النمو (آلاف المتزامنين)
1. **Postgres + Pooling**: Neon/Supabase pooler — أول عنق زجاجة هو SQLite (كاتب واحد).
2. **Limiter مشترك**: استبدل `src/lib/rate-limit.ts` (ذاكرة محلية لكل نسخة) بـ Redis (Upstash مثلاً) لو شغلت أكثر من نسخة.
3. **نسخ متعددة**: Next standalone خلف Load Balancer — الجلسات في القاعدة أصلًا فأي نسخة تخدم أي مستخدم.
4. **CDN** للأصول الثابتة (تلقائي على Vercel).
5. **مراقبة**: سجلات المزود + `AuditLog` + عدّادات `/api/admin/overview` تكفي للبداية؛ أضف Sentry عند الحاجة.

### إجهاد الحجز (فتح الحجز لحظة معينة)
- المقعد بيتحجز بمعاملة قصيرة جدًا وبحد أقصى — السعة 500 مقعد ممكن تُستهلك في ثوانٍ بدون تضارب لأن العدادات ذرّية.
- لو متوقّع ضغط أكبر بكثير: زوّد نسخة التطبيق + Postgres pool أقصى، والأفضل تفتح الحجز على مراحل (دفعات دعوات أولًا — الموجود في التصميم أصلًا بوابة الدعوات).

## 6) النسخ الاحتياطي والاسترجاع

- Postgres مُدار: فعّل PITR/النسخ اليومي من لوحة المزود.
- `Setting` و `PaymentAccount` بيانات تشغيلية — موجودة في القاعدة، فالنسخة الاحتياطية تغطيها.
- اختبار الاسترجاع مرة قبل الإطلاق: استعادة نسخة على قاعدة اختبار والتأكد من دخول مستخدم وتذكرة QR.
