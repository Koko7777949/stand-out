# Stand Out — منصة حجز التذاكر الرسمية

> **Stand Out** | تذكرة رقمية بـ QR، دفع عبر InstaPay والمحافظ المصرية، بوابة دعوات بالنقاط، ولوحة تحكم كاملة.
> أول فعالية على المنصة: **Build Your Future Summit 2026** — السبت 21 نوفمبر 2026، The GrEEK Campus، وسط البلد، القاهرة.

منصة حجز تذاكر إنتاجية كاملة: تسجيل بتحقق حقيقي (واتساب للرقم الموبايل / Resend للإيميل)، حجز مقعد مضمون برقم تسلسلي وتذكرة QR موقّعة، بوابة دفع تفتح تطبيق المحفظة أو انستاباي مباشرة على رقم الاستلام الذي يحدده الأدمن، تذكرة لا تُحمّل إلا بعد تأكيد الدفع، بوابة دعوات شخصية `/i/{code}` بنقاط تُحسب فقط عندما يسجّل صديقك ويؤكد حسابه من رابطك، متجر جوائز، ولوحة تحكم أدمن بطبقتي تحقق تتحكم في كل شيء.

## المميزات

### للجمهور
- **صفحة هبوط** بهوية بصرية مرسومة يدويًا (نمط الستيكرز) — GSAP + Lenis + مكونات بأسلوب reactbits، متجاوبة بالكامل، RTL عربي.
- **تسجيل دخول حقيقي**: رقم موبايل (كود تحقق **واتساب عبر UltraMsg** — بدون SMS نهائيًا) أو إيميل (كود تحقق عبر **Resend**).
- **حجز مقعد**: الاسم زي الهوية + السن + المحافظة + الموافقة على الشروط — النظام يصدر رقمًا تسلسليًا `STO26-XXXXXXX` ويحجز المقعد 15 دقيقة أثناء الدفع.
- **بوابة دفع مؤمّنة**: InstaPay + فودافون كاش + أورنج كاش + e& money + WE Pay. زر الدفع **يفتح التطبيق نفسه** على رقم الاستلام المحدد من الأدمن (deep link)، مع نسخ تلقائي للعنوان والمرجع، ومساحة **كود السفير** تحت طلب المراجعة لمن جاء بدعوة أمباسدور.
- **قفل التحميل قبل الدفع**: التذكرة تظهر كمعاينة مقفولة بعلامة مائية — زر التحميل (PNG + PDF بـ QR موقّع HMAC) لا يظهر إلا بعد اعتماد الدفع.
- **بوابة مشاركة**: رابط شخصي `/i/{code}` + أزرار واتساب/تليجرام/فيسبوك/X + ليدربورد + مستويات بونص + إخفاء الاسم.
- **متجر نقاط**: استبدال النقاط بجوائز تُسلَّم في الفعالية من كشك الفريق.

### للأدمن
- لوحة تحكم من 9 أقسام (نظرة عامة / الدفعات / الفعاليات / حسابات الاستلام / السفراء / المستخدمين / المسؤولين / الاستبدالات / الإعدادات).
- دخول بطبقتين: كود تحقق واتساب على رقم مسموح + كلمة سر (scrypt).
- اعتماد/رفض الدفعات اليدوية (ومنها كود السفير المسجل على كل طلب)، مراجعة الإحالات المشبوهة، إدارة فعاليات متعددة، إدارة أكواد السفراء بعدّاد استخدامات، تعديل أرقام الاستلام و**قوالب الروابط المباشرة**، تعيين مسؤولين جدد، متابعة سجل تدقيق كامل.

## البدء السريع

المتطلبات: Node.js 20+ (أو Bun) و Prisma.

```bash
# 1) التبعيات
bun install        # أو npm install

# 2) قاعدة البيانات (SQLite افتراضيًا)
bun run db:push

# 3) متغيرات البيئة
cp .env.example .env
#   وأضف ULTRAMSG_INSTANCE/ULTRAMSG_TOKEN (واتساب) و RESEND_API_KEY (إيميل) — الباقي اختياري

# 4) التشغيل
bun run dev        # http://localhost:3000

# فحص الجودة
bun run lint
```

> أول تشغيل للسيرفر يعمل **Bootstrap تلقائيًا**: يرفع رقمَي المسؤولين `01200506224` و `01107548985` إلى `super_admin`، وينشئ كلمة سر الأدمن الافتراضية، ويسجّل حسابات الاستلام الافتراضية (انستاباي + المحافظات).

### سكربتات متاحة

| الأمر | الوظيفة |
|---|---|
| `bun run dev` | تشغيل بيئة التطوير على 3000 |
| `bun run lint` | فحص ESLint |
| `bun run db:push` | دفع الـ schema لقاعدة البيانات |
| `bun run db:generate` | توليد Prisma Client |
| `bun run build` + `bun run start` | بناء إنتاجي (standalone) وتشغيله |

## متغيرات البيئة

انسخ `.env.example` إلى `.env` وعدّل القيم. **كل المفاتيح السرية تبقى على السيرفر — لا شيء منها يصل للمتصفح.**

| المتغير | إلزامي؟ | الوظيفة |
|---|---|---|
| `DATABASE_URL` | نعم | SQLite افتراضيًا: `file:./db/custom.db` — وفي الإنتاج: Postgres (انظر [النشر](#النشر-للإنتاج-والاستضافة)) |
| `SESSION_SECRET` | نعم | مفتاح تجزئة الجلسات وتوقيع تذاكر الأدمن والـ IP — **ولّد قيمة عشوائية 64 حرفًا** |
| `QR_SIGNING_SECRET` | يُفضَّل | توقيع توكنات QR والويبهوك — لو فاضي بيستخدم قيمة داخلية (غيّرها في الإنتاج) |
| `RESEND_API_KEY` | للإيميل | مفتاح Resend — أكواد التحقق للإيميل |
| `EMAIL_FROM` | اختياري | مثل `Stand Out <no-reply@yourdomain.com>` |
| `ADMIN_PHONES` | اختياري | أرقام المسؤولين مفصولة بفواصل — الافتراضي `01200506224,01107548985` |
| `ULTRAMSG_INSTANCE` / `ULTRAMSG_TOKEN` | للموبايل | واتساب UltraMsg — القناة الوحيدة لأكواد الموبايل (بدون SMS) |

> **ملحوظة أمنية:** مفاتيح الإيميل (Resend/بوابة مخصصة) يمكن أيضًا تدبيرها من لوحة الأدمن (تاب الإعدادات) بدون إعادة نشر. أما بيانات واتساب (UltraMsg) فمن متغيرات البيئة على السيرفر **فقط** — مش موجودة في اللوحة أبدًا. لا تضع أي مفتاح داخل ملفات الكود إطلاقًا، ولا ترفع `.env` إلى Git (وهو مستبعد في `.gitignore`).

## مزود الرسائل

**الموبايل = واتساب فقط (UltraMsg) — بدون SMS نهائيًا**: كود التحقق بيوصل رسالة واتساب على الرقم اللي الموقع عايز يتحقق منه. **الإيميل = Resend** (أو بوابة مخصصة POST JSON). التواقيع الحقيقية للمزودين في `src/lib/notify.ts`.

- صفحة إعدادات مزود واتساب/SMS **اتشالت من لوحة الأدمن** بطلب صاحب الموقع — بيانات UltraMsg تُضبط من متغيرات البيئة على السيرفر فقط، وأي قيم قديمة في قاعدة البيانات بتتجاهل تلقائيًا.
- الأرقام تُحوَّل تلقائيًا للصيغة الدولية: `01200506224` ← `201200506224`.
- **وضع التطوير**: لو UltraMsg غير مربوط (متغيرات البيئة فاضية)، الكود يظهر على الشاشة (Dev Hint) حتى تختبر كامل الرحلة. في الإنتاج: اربط UltraMsg + شغّل `hideDevOtp` من تاب الإعدادات فيختفي تمامًا.

### واتساب — UltraMsg (المزود المعتمد)

| المطلوب | صيغة الطلب الفعلية |
|---|---|
| Instance ID + Token (من البيئة) | `POST https://api.ultramsg.com/{instance}/messages/chat` — JSON بالصيغة الرسمية: `{"token":"…","to":"201200506224","body":"كود التحقق…","priority":10,"referenceId":"","msgId":"","mentions":""}` — النجاح: `{"sent":"true","id":"…"}` والرفض: `{"success":"false","error":"…"}` |

### ربط UltraMsg خطوة بخطوة (واتساب)

1. اعمل حساب على [ultramsg.com](https://ultramsg.com) وأنشئ **Instance** جديدًا، ثم اربط رقم الواتساب الخاص بالـ Instance بمسح QR من تطبيق واتساب.
2. من صفحة الـ Instance انسخ `Instance ID` (مثل `instance95000`) و `Token`.
3. حطهم في `.env` على السيرفر ثم أعد تشغيل التطبيق:
   ```
   ULTRAMSG_INSTANCE="instance95000"
   ULTRAMSG_TOKEN="your-token-here"
   ```
4. من تاب الإعدادات اضغط **تجربة واتساب** واكتب رقمك — لو الرسالة وصلت يبقى كل أكواد الدخول هتوصل واتساب فورًا.
5. قبل الإطلاق الفعلي فعّل `hideDevOtp` من نفس التاب حتى لا يظهر كود التحقق على الشاشة أبدًا.

ملاحظات:
- الطلب المرسل **مطابق للمثال الرسمي للمزود**: `token` + `to` + `body` + `priority: 10` + `referenceId` + `msgId` + `mentions` — والرقم بيتبعت دوليًا `201200506224`.
- UltraMsg أحيانًا يرد `HTTP 200` مع `{"success":"false","error":"…"}` — النظام بيكتشف الرفض ده ويسجّل الخطأ في السجل (الكود بيرجع للشاشة في وضع التطوير بس).
- الـ Instance لازم يكون متصل (الجهاز اللي فيه واتساب مربوط) — لو فصل، الرسائل هتفشل لحد ما يرجع.

### Email — Resend

```
POST https://api.resend.com/emails
Authorization: Bearer {RESEND_API_KEY}
Content-Type: application/json

{
  "from": "Stand Out <onboarding@resend.dev>",
  "to": ["user@example.com"],
  "subject": "كود التحقق — Stand Out",
  "text": "كود التحقق — Stand Out — كود التحقق: 123456 (صالح 5 دقايق)",
  "html": "… قالب HTML بهوية Stand Out …"
}
```

- النجاح: `200 {"id":"…"}`. خطة Resend المجانية: 100 رسالة/يوم، 3000/شهر — كافية لأكواد التحقق في البداية.
- `onboarding@resend.dev` يصلح للاختبار فقط؛ بعد ربط دومينك فعّل الدومين في Resend وغيّر `emailFromAddress` من تاب الإعدادات.

## السفراء وأكواد البرومو

برنامج السفراء بيخلي كل أمباسدور ليه كود برومو بيتكتب في مساحة مخصصة **تحت طلب المراجعة** في بوابة الدفع.

### تجربة العميل
1. العميل بيوصل لخطوة الدفع (ملخص الطلب → اختيار الطريقة → تعليمات التحويل).
2. تحت طلب المراجعة (قبل أو حتى بعد الضغط على "تم التحويل — أكّد الدفع") لاقي مساحة **"كود السفير (اختياري)"** — لو جاي تبع أمباسدور بيكتب الكود ويضغط **تطبيق**.
3. النظام بيتحقق إن الكود موجود ومفعّل، وبيربطه بالطلب نهائيًا (مش بيتغير بعدها)، وبيظهر شريط أخضر باسم السفير.

### إدارة السفراء (الأدمن)
- تاب **السفراء** في اللوحة: إضافة كود (حروف إنجليزية/أرقام 3-24 خانة) + اسم + ملاحظة، تفعيل/إيقاف، حذف.
- عدّاد **الاستخدامات** بيزيد تلقائيًا مع كل طلب بيتسجل بالكود — والأكواد المسجلة بتظهر في تاب الدفعات جنب كل عملية.
- أكواد تجريبية جاهزة من الـ seed: `BYF-MAZEN` و `BYF-SARA`.

### الـ API
| Endpoint | الوظيفة |
|---|---|
| `POST /api/promo` | تحقق عام من الكود (يرجع اسم السفير فقط — بدون بيانات حساسة) |
| `POST /api/orders/{orderId}/promo` | ربط الكود بالطلب (مالك الطلب فقط، مرة واحدة) |
| `GET/POST/PATCH/DELETE /api/admin/ambassadors` | إدارة السفراء من اللوحة |

## الدفع والروابط المباشرة

المطلوب: عند الضغط على "الدفع" يتم **التحويل مباشرة إلى تطبيق المحفظة أو انستاباي** لإتمام الدفع على الرقم الذي يحدده الأدمن، حسب نوع الطريقة.

### كيف تعمل

1. الأدمن يسجل حسابات الاستلام من اللوحة (تاب **حسابات الاستلام**): الطريقة، الاسم، الرقم/العنوان، **قالب الرابط المباشر**، وتعليمات.
2. المستخدم يختار الطريقة → السيرفر ينشئ `Payment` بمرجع عملية ويعيد التعليمات + الرابط المباشر المولّد.
3. زر "افتح التطبيق" ينقل المستخدم للمحفظة/انستاباي بالرقم والمبلغ والمرجع جاهزين.
4. بعد التحويل يضغط "تم التحويل" → الطلب يدخل **مراجعة الفريق** (والحجز يمتد 24 ساعة).
5. الأدمن يعتمد من تاب الدفعات → التذكرة تتحرر فورًا ويظهر زر التحميل.

### القالب — المتغيرات المتاحة

| المتغير | يُستبدل بـ |
|---|---|
| `{account}` | رقم/عنوان الاستلام من حسابات الاستلام |
| `{amount}` | المبلغ بالجنيه (من السيرفر — لا يُقرأ من العميل أبدًا) |
| `{reference}` | مرجع العملية (يُكتب في الملاحظة لتمييز التحويل) |

### قوالب جاهزة (محفوظة افتراضيًا عند أول تشغيل)

| الطريقة | القالب الافتراضي |
|---|---|
| InstaPay | `ipn://{account}?amount={amount}&ref={reference}` |
| Vodafone Cash | `tel:*9*7*{account}*{amount}#` |
| Orange Cash | `tel:*9*79*{account}*{amount}#` |
| e& money (اتصالات كاش) | `tel:*9*7*{account}*{amount}#` |
| WE Pay | `tel:*9*7*{account}*{amount}#` |

> روابط USSD (`tel:`) تُشفَّر تلقائيًا (`*` → `%2A` و `#` → `%23`) لتفتح اتصال صحيح على آيفون وأندرويد. أكواد التحويل تختلف أحيانًا حسب المزود — راجعها وعدّل القالب من اللوحة مباشرة بدون أي كود. أي قالب بنظام آخر (`scheme://…` أو `https://…`) مسموح؛ أما `javascript:` و `data:` فمرفوضان دائمًا.

### لماذا يوجد "تم التحويل" ثم مراجعة أدمن؟

التحويل على انستاباي والمحافظ يدوي من طرف إلى طرف، ومفيش ويبهوك رسمي يبلغنا فورًا. لذلك التأكيد النهائي بيحصل من **الاعتماد البشري** (أدمن يشوف المبلغ في حساب الاستلام ويطابق المرجع) أو من **ويبهوك مزود دفع حقيقي** (Paymob/Kashier) موقّع بـ HMAC عبر `/api/webhooks/payments` — الاتنين مدعومين، والثاني جاهز عندما تشترك في بوابة آلية.

## لوحة تحكم الأدمن

الدخول: نفس بوابة تسجيل الدخول برقم **مسموح فقط** → كود تحقق واتساب → **كلمة سر الأدمن** (الطبقة الثانية). بدون الاثنين لا يوجد وصول.

- الأرقام المعتمدة افتراضيًا: `01200506224` و `01107548985` (تُضاف إليها أرقام من تاب المسؤولين أو متغير `ADMIN_PHONES`).
- كلمة السر الافتراضية بعد أول تشغيل: `StandOut@2026` — **غيّرها فورًا من تاب الإعدادات** (تُخزَّن scrypt + salt، ولا تظهر أبدًا في أي قراءة).

| التاب | ماذا تتحكم فيه |
|---|---|
| **نظرة عامة** | مؤشرات: الحجوزات، الدفعات المؤكدة، الإيراد، الإحالات المؤهلة، آخر النشاطات |
| **الدفعات** | الدفعات المعلّقة للمراجعة: تفاصيل + مرجع العملية + **كود السفير المسجل** → تأكيد الاستلام / رفض + قائمة الإحالات المشبوهة |
| **الفعاليات** | إنشاء وتعديل الفعاليات: الاسم، الموعد، المكان، السعة، السعر، عمر الحضور، مدة الاحتفاظ بالمقعد، فتح/غلق الحجز، **تفعيل فعالية واحدة فقط للعامة**، نص المشاركة |
| **حسابات الاستلام** | أرقام وعرافين استلام الفلوس لكل طريقة + **قوالب الروابط المباشرة** + تعليمات + ترتيب الظهور + تفعيل/إيقاف |
| **السفراء** | أكواد البرومو: إضافة، تفعيل/إيقاف، حذف، ومتابعة عدّاد الاستخدامات لكل سفير |
| **المستخدمون** | بحث، حظر/فك حظر، تغيير الدور |
| **المسؤولين** | تعيين مسؤولين جدد برقم موبايل، رفعهم إلى admin أو super_admin، إزالتهم |
| **الاستبدالات** | طلبات الجوائز: تعليمها fulfilled أو إلغاؤها (والنقاط ترجع) |
| **الإعدادات** | اسم الموقع، بيانات الدعم، مزود الإيميل، إخفاء كود التطوير، تجربة واتساب/إيميل، **تغيير كلمة سر الأدمن** — (واتساب UltraMsg من متغيرات البيئة فقط، وصفحة مزود واتساب/SMS اتشالت من اللوحة) |

كل فعل إداري حساس يُسجَّل في **AuditLog** (من، ماذا، على أي كيان، متى).

> للجمهور: لا شيء من هذا يظهر — الموقع العام يعرض صفحة الفعالية والحجز فقط، ولوحة الأدمن تفتح للدور المصرح بعد الطبقتين.

## بوابة الدعوات والنقاط

- كل مستخدم يحصل على كود دعوة فريد — الرابط: `https://{الدومين}/i/{code}` (أو `/?ref={code}` — كلاهما يعمل).
- **first-touch**: الكود يُسجَّل في كوكي + localStorage لـ 30 يومًا ويُحصى كنقرة في `ReferralClick`.
- **قاعدة النقاط**: الصديق لازم يفتح رابطك، يسجل حسابًا جديدًا، **ويؤكد رقمه** — عندها تتحسب نقطة في رصيدك (تُضبط `pointsPerReferral` من تاب الإعدادات). مجرد فتح الرابط أو التسجيل بدون تأكيد = لا نقاط.
- الحماية: الـ IP يُخزَّن hashed، الإحالات تتدقق (نفس الجهاز/حسابات مكررة) وتظهر للأدمن في طابور مراجعة، والإحالة المرفوضة تُسحب نقاطها.
- المستويات: بونص عند 5 و10 صديق مؤهل — والنقاط تُستبدل من متجر الجوائز (يديره الأدمن).

## الأمان

| الطبقة | التفاصيل |
|---|---|
| **أكواد التحقق** | sha256 + salt لكل قناة، صلاحية 5 دقائق، 5 محاولات كحد أقصى، فترة إعادة إرسال 60 ثانية، حدود: 3 طلبات/10 دقائق لكل رقم و 15 طلب/ساعة لكل IP |
| **الجلسات** | توكن عشوائي 32 بايت، يُخزَّن hashed في القاعدة (تسريب القاعدة لا يكشف التوكنات)، كوكي httpOnly SameSite=Lax، إبطال فوري عند الخروج، 30 يومًا |
| **دخول الأدمن** | طبقتان إلزاميتان: واتساب OTP على رقم مسموح + كلمة سر scrypt — وتذكرة وسيطة موقّعة HMAC صالحة 5 دقائق فقط بين الطبقتين |
| **التذكرة** | رقم تسلسلي Crockford Base32 + خانة فحص، توكن QR موقّع HMAC-SHA256 بدون أي بيانات شخصية، أول مسح = دخول (رفض الاستخدام المتكرر) |
| **الدفع** | المبلغ من السيرفر دائمًا، Idempotency لكل عملية، معاملات ذرّية للعدّاد (ضد البيع الزائد)، ويبهوك موقّع HMAC، تعارض المراجع يُرفض 409 |
| **الروابط المباشرة** | قوالب الأدمن تُفحص: مسموح `https:` / `ipn:` / `tel:` / scheme صريح — `javascript:` و `data:` مرفوضان |
| **الخصوصية** | IP و User-Agent يُخزَّنان hashed فقط، لا تُخزَّن بيانات كروت أو محافظ إطلاقًا، سياسة خصوصية وشروط معروضة للجمهور |
| **الحد من الضغط** | limiter في الذاكرة على كل المسارات الحساسة (OTP، تأكيد الدفع، الاستبدال…) |
| **سجل التدقيق** | AuditLog لكل فعل إداري وحساس |

## مرجع الـ API

## قاعدة البيانات

Prisma + SQLite افتراضيًا (`db/custom.db` — مستبعد من Git). النماذج:

`User` · `Session` · `OtpCode` · `Event` · `Order` · `Payment` · `Ticket` · `Referral` · `ReferralClick` · `PointsTier` · `PointsLedger` · `Reward` · `Redemption` · `PaymentAccount` · **`Ambassador`** · `Setting` · `AuditLog`

مبادئ مثبتة في الـ schema:
- **PointsLedger** append-only — دفتر نقاط لا يُعدَّل ولا يُحذف.
- فهارس على كل مسارات القراءة الساخنة (`Order[status,holdExpiresAt]`، `Referral[referrerId,status]`، `Ticket[serial]` …).
- عدّاد المقاعد عملية SQL ذرّية داخل Transaction.
- للانتقال إلى Postgres لاحقًا: غيّر `provider` في `prisma/schema.prisma` و `DATABASE_URL` ثم `bun run db:push` — بدون أي تعديل في الكود.

## النشر للإنتاج والاستضافة

> التفصيل الكامل خطوة بخطوة في [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md).

**الخلاصة:** GitHub Pages يعرض HTML ثابت فقط — لا يخدم قاعدة بيانات ولا جلسات ولا أكواد تحقق، فلا يصلح لواجهة خلفية حقيقية. الاختيارات العملية:

## الأداء وعدد المستخدمين المتزامنين

- **الواجهة**: صفحة واحدة خفيفة، صور محسّنة، الحركة على GPU (GSAP/Lenis)، و `prefers-reduced-motion` محترم.
- **السيرفر**: بنية standalone، استعلامات مفهرسة، تحرير المقاعد المعلقة تلقائيًا (لا تراكم)، معاملات قصيرة، Idempotency على الدفع.
- **الحد من الضغط** يحمي المسارات الحساسة من المزاحمة أثناء الذروة (فتح الحجز).
- **مسار التوسع** (عند آلاف المتزامنين): SQLite → Postgres + Pooling، limiter مشترك على Redis، ونسخ متعددة خلف Load Balancer — التفاصيل في [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md).

## الأسئلة المتكررة التشغيلية

**الكود بيظهر على الشاشة في التطوير — ده طبيعي؟** نعم؛ لأنه UltraMsg مش مربوط لسه. حط `ULTRAMSG_INSTANCE` و `ULTRAMSG_TOKEN` في `.env` على السيرفر وأعد التشغيل — وفي الإنتاج فعّل `hideDevOtp` فيختفي.

**أضيف كود أمباسدور منين؟** تاب **السفراء** في اللوحة → ضيف الكود والاسم — العميل بيكتبه في مساحة "كود السفير" تحت طلب المراجعة، وكل استخدام بيتحسب تلقائيًا.

**أغيّر رقم الاستلام منين؟** لوحة الأدمن → تاب **حسابات الاستلام** — الرقم والاسم والقالب والتعليمات، بدون أي كود.

**أضيف فعالية تانية؟** تاب **الفعاليات** → إنشاء فعالية → فعّلها (التفعيل ينقل الظهور العام إليها فورًا).

**المستخدم قال "حوّلت" وأنا مش شايف الفلوس؟** تاب **الدفعات** → طابق مرجع العملية مع كشف حسابك → اعتمد أو ارفض.

**كلمة سر الأدمن؟** `StandOut@2026` عند أول تشغيل — غيّرها فورًا من تاب الإعدادات.
